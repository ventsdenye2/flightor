# 多城机票路线规划：产品设计与 Case 评测方案

## 1. 功能定义

做一个纯粹的飞行路线规划功能：

- 输入：一段长自然语言指令（假期窗口、可玩天数、签证、省钱偏好等）
- 输出：2-3 条候选路线，每条包含城市顺序、每段航班（日期/时刻/价格）、总价
- 不做酒店、景点、交易，只解决"这几个城市怎么串起来飞最便宜"

与现有 FlightOR 的关系：复用 chatAgent 的槽位解析、SerpApi 日期粒度缓存、备选攻略卡的呈现模式，新增多城路线搜索引擎。

## 2. 典型需求（Case 0，来自真实用户）

原指令：

> 现在是 8 月下旬，我 9 月 1 号到 9 月 20 号之间有 10-20 天假期，其中 8 天可以出去玩。
> 这 8 天我想去欧洲尽可能多的城市，我有申根签。
> 我想省钱，希望晚上坐飞机、早晨到，省一天住宿。
> 路线要尽可能合理，比如从法国出发，可以飞瑞士、飞德国，怎么串起来最便宜。

期望的结构化解析结果：

| 字段 | 值 |
|---|---|
| 假期窗口 | 2026-09-01 ~ 2026-09-20 |
| 可玩天数 | 8 天 |
| 出发地 | 用户所在城市（缺失则追问） |
| 目的区域 | 欧洲 · 申根区 |
| 签证 | 持申根签 → 候选池 = 申根国家城市 |
| 城市数目标 | 尽可能多（上限由天数和夜航效率推算） |
| 夜航偏好 | 强：20:00 后起飞、09:00 前到达，等效省一晚住宿 |
| 优化目标 | 总价最低为主，路线不回溯为辅 |

## 3. 功能模块

### M1 长指令解析（扩展现有 chatAgent）

把长指令解析为结构化约束（见 Case 0 的字段表）。原则与现有一致：

- 缺失关键字段（出发地、天数）时追问，不编造
- 解析完成后回显确认，用户可逐条修改
- 冲突约束（如"5 天玩 8 城 + 只要直飞"）要显式指出并给降级选项

### M2 约束与候选池

- 申根城市机场表：约 20 个热门城市，含经纬度（用于地理回溯惩罚）、国家签证属性
- 签证规则：持申根签 → 申根池；无申根签 → 免签/落地签池（塞尔维亚、泰国等）
- 必去/排除城市：作为搜索的硬约束

### M3 分段价格探测（复用 SerpApi 日期粒度缓存）

- 探测对象：出发地 ⇄ 欧洲入口城市的长途段 + 欧洲城市间短途段
- 成本控制分三步：
  1. 地理启发先筛出 Top-K 城市（不做全量两两探测，20 城全探需 380 个 OD 组合，配额不允许）
  2. 同一 OD + 日期窗口命中缓存不重复探测
  3. 搜索阶段先用缓存价格估价，仅在路线确定后对最终航段做精确探测

### M4 路线搜索引擎（核心，树状搜索）

问题定义：带约束的旅行商问题（TSP），城市数 ≤ 8，可用分支定界精确求解。

状态定义：

```
(当前城市, 当前日期, 已访问集合, 累计成本, 夜航段数)
```

扩展规则：从当前城市选下一城市 + 出发日期，直到天数用尽或达到城市上限，最后接回程段。

剪枝条件：

1. 累计成本 + 下界 ≥ 当前最优解，剪掉（下界 = 回程最低价 + 剩余必走段的最低价估计）
2. 已用天数超过可玩天数
3. 地理回溯超过阈值（如向西飞了又向东飞）

评分函数：

- 第一目标：总价（长途段 + 欧洲内段）
- 夜航奖励：20:00 后起飞且 09:00 前到达的段，等效扣减一晚住宿成本（约 ¥400），计入总成本
- 第二排序：城市数量，再是路线总里程

降级策略：候选城市多时改用 beam search，每层保留成本最优的 N 个状态。

### M5 方案收敛与呈现

- 收敛出 2-3 条差异化路线：总价最低 / 城市最多 / 夜航最省住宿
- 每条路线呈现：城市顺序条（巴黎 → 苏黎世 → 慕尼黑 → …）、每段航班的日期与时刻、总价、省住宿晚数
- 沿用现有备选攻略卡交互：对话内直接选一条，进入详情

## 4. Case 集

每个 case 包含：输入指令、期望解析、期望输出、通过标准。

### Case 1 标准多城案例（即 Case 0）

- 输入：第 2 节原指令
- 期望输出：2-3 条路线，每条 4-6 个城市；路线地理上连贯（如巴黎 → 苏黎世 → 慕尼黑 → 维也纳，不出现巴黎 → 雅典 → 苏黎世这类回溯）；标注夜航段和节省的住宿晚数
- 通过标准：解析字段全对；路线不回溯；总价在各候选中确实最低或接近最低

### Case 2 预算优先短途

- 输入："下周五晚出发周日回，上海出发，去东南亚，越便宜越好"
- 期望：窗口识别为 3 天；候选池 2-3 城（曼谷/吉隆坡/新加坡）；不出现超过 3 天的方案
- 通过标准：短窗口处理正确，不过度规划

### Case 3 必去城市约束

- 输入："十月中旬 10 天，巴黎和罗马必须去，其他城市看着加，有申根签，深圳出发"
- 期望：两条路线都含巴黎和罗马；两城先后顺序按总价择优；补充城市不超过天数承载
- 通过标准：硬约束不被丢弃，顺序参与优化

### Case 4 模糊需求

- 输入："九月想出去玩，便宜点"
- 期望：追问出发地、天数、签证情况，不生成方案，不编造约束
- 通过标准：追问内容覆盖缺失的必填字段

### Case 5 约束冲突

- 输入："5 天假期想去欧洲 8 个城市，全部要直飞"
- 期望：指出冲突（5 天无法覆盖 8 城，且欧洲城际直飞有限），给出降级选项（减少城市数 / 接受中转）
- 通过标准：冲突被显式识别，不硬出不可行方案

### Case 6 签证约束切换

- 输入："没有申根签，10 月想出国玩 8 天，多去几个地方"
- 期望：候选池切换为免签/落地签国家；提示申根城市不可达
- 通过标准：签证规则正确生效，不出现申根城市

### Case 7 预算过低

- 输入："9 月 1 号到 9 月 10 号，8 天，去欧洲 4 个城市，预算 2000，深圳出发，有申根签"
- 期望：预算作为硬约束，返回空结果或全部路线总价 ≤ 2000；提示放宽预算
- 通过标准：不出超预算方案，不崩溃

### Case 8 中文数字预算

- 输入："9 月 1 号到 9 月 20 号出去玩 8 天，欧洲尽可能多城市，有申根签，深圳出发，预算一万五"
- 期望："一万五"解析为 15000；全部路线总价 ≤ 15000
- 通过标准：中文数字（一万五/八千/两万）解析正确，预算约束生效

### Case 9 极短窗口

- 输入："9 月 5 号到 9 月 6 号，2 天假期，欧洲多城，深圳出发，有申根签"
- 期望：2 天无法支撑多城，返回空结果并提示延长行程；不崩溃
- 通过标准：边界输入下引擎稳定，不硬凑方案

## 5. 评测流程（飞书多维表格）

### 表格字段设计

| 字段 | 说明 |
|---|---|
| Case 编号 | Case 1 ~ Case N |
| 输入指令 | 原文 |
| 期望输出要点 | 通过标准列表 |
| 实际输出 | 系统返回截图或文本 |
| 评级 | 1 / 2 / 3 / 4 |
| 问题环节 | 单选：解析 / 候选池 / 探测 / 搜索 / 呈现 |
| 修复记录 | 本轮改了什么 |
| 回归结果 | 修复后重跑该 case 的评级 |
| 版本 | 对应 prompt / 算法配置版本 |

### 评级标准

- 4 分：关键字段全部正确，方案可直接执行
- 3 分：方案可执行，次要字段有瑕疵（呈现、次要约束未满足）
- 2 分：方向对但关键字段错误（价格、日期、路线顺序、签证）
- 1 分：不可用，或编造了不存在的航班/价格

### 迭代循环

1. 收集 case：多人各自写真实需求指令，汇入表格
2. 跑 case：统一版本下运行，记录实际输出
3. 评级与归因：按上表打分，标注问题环节
4. 修复：按环节归因修 prompt、候选池数据或搜索配置
5. 回归：修复后重跑全部 case，防止改好一个改坏另一个
6. 蒸馏：把稳定 4 分的"指令 → 最优解"对沉淀为 few-shot 示例和规则，注入解析 prompt 与搜索配置，形成下一轮基线

## 6. 人员分工

| 角色 | 人数 | 职责 |
|---|---|---|
| case 出题人 | 3-5 人 | 写真实出行指令，覆盖不同出行习惯（穷游/舒适/亲子） |
| 评测人 | 1 人 | 统一评级口径，维护飞书表格 |
| 算法与产品负责人 | 1 人 | 归因、修复、蒸馏、版本管理 |

## 7. 实施顺序

| 阶段 | 内容 | 依赖 |
|---|---|---|
| P1 | M1 解析扩展 + M4 搜索骨架（用 mock 价格跑通 Case 1/4/5） | 现有 chatAgent |
| P2 | M2 申根城市池 + M3 真实价格探测接入（已完成：城市池含免签切换、逐段探测确认 probe.js、真实数据优先于估算价的剪枝/截断保护、解析换 LLM llmParse.js 带规则兜底、云函数化 cloud/routePlanner） | SerpApi 缓存层 |
| P3 | M5 呈现 + M6 case 回归流程跑起来（已完成对话内路线卡：chatStore 多城意图路由 + plan 页路线卡 UI，含航段展开、实时/估算标记、核实实时报价按钮；云函数上传与真机验证待做） | 飞书表格建好、出题人到位 |
