# DSH Provider recovery (2026-09-27)

Status: implemented in isolated `codex/dsh-backend` worker; local verification below. This is not a live Provider or H5 acceptance result.

The worker keeps the official DSH AgentLoop. Its `llm/stream` boundary admits and settles each attempted model request separately using the existing budget bridge. The SDK's own retry count remains zero. A transient `TRANSPORT`, `TIMEOUT`, `RATE_LIMIT` (HTTP 429), or `SERVER` (HTTP 5xx) terminal failure can dispatch at most two additional attempts, with 250 ms and 750 ms abortable pauses. Recovery stops on cancellation, after any emitted stream chunk, or for authentication, invalid request, account quota, context validation and other unclassified failures. No tool, commit, or partial answer is replayed. The existing turn timeout is still enforced by the parent service, and the provider request timeout remains 60 seconds. There is no fixed worker-wide model-call count; the budget ledger and outer turn lifecycle remain the authorities. `calls` counts admitted model attempts and `providerRetries` counts extra dispatches in the turn result.

Provider failures use the SDK's structured failure code, never provider message text, for retry decisions. The worker returns an optional safe `errorCode` and includes safe `failureCode` in failed model receipts. Usage-only stream preludes are held until outcome is known; they do not falsely mark a failed request as partial answer output. This report concerns model HTTP recovery; web search/fetch retains its separate receipt and failure policy. No real paid request was made for this change.

Validation: `node backend/dsh-runtime/test/provider-recovery.test.mjs` passed 2/2 (transient/nontransient classes, cap, output guard and abortable delay). `node backend/dsh-runtime/test/provider-http.test.mjs` passed 5/5 against loopback mock HTTP through the actual worker and SDK: HTTP 503→200 had two identical request bodies, two unique budget admissions and two receipts, one retry and a recovered reply; HTTP 401 had one request/receipt; three HTTP 503 responses stopped after two retries with three failed receipts; HTTP 429→200 retried once; cancellation after the first failed receipt prevented a second HTTP request and preserved the single receipt. `node backend/dsh-runtime/test/worker.test.mjs` passed 1/1 fixture AgentLoop regression. `node scripts/check-docs.cjs` passed (107 Markdown files, 652 links, batch docs check); `git diff --check` and worker syntax passed. These runs used a dummy local key and made no real paid requests. Live Provider behavior, a true in-flight timeout/cancel receipt, and H5 remain unverified here.
