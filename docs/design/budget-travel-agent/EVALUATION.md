# 运行测量、多用户案例与 DSH 决策协议

2026-09-20，**B5 埋点已实施；G1 数据库及两条真实 Provider 保存/恢复契约通过，但真实内容出现活动日期硬错误，G1 不放行；平台与正式评测批次未执行**。实测见 [G1 报告](G1_LIVE_2026-09-20.md)，实现入口：[RUNTIME_PLAN](RUNTIME_PLAN.md)。执行编排指测试场景和调用顺序，不要求新增多个旅行 Agent 或 Codex 子代理。

## 1. 顺序与对照组

1. 固定现有源码/数据基线 A：当前 main `9954c34`，记录 dirty diff/hash；历史东京回执仅作诊断，不能与新场景直接算提速比。
2. 在现有 runtime 完成 B：精简状态/引用/修复/交付路径，通过领域与数据库验证，并跑通一条真实“已选航班→保存→刷新恢复”及自备机票攻略路径。
3. 再做 B 正式运行时间测量与 A/B 多案例对照：先用相同归档事实/研究输入隔离编排，再做小规模实时 Provider 验证。旧快照仅用于回放，不作为当前有效报价。
4. 汇总性能、质量、失败模式，输出 DSH 决策。只有证据支持才建立 C；C 使用与 B 相同业务接口和执行目标。

三层证据不能混合：确定性 fixture/stub 验证契约但不证明 LLM 性能；真实 Planner + 冻结研究/航班验证模型编排；真实 Planner + 实时 Provider 验证完整线上链路。严格 HTTP 回放不运行模型，不能算一次 Agent 性能测试。

## 3. 运行编排

- 第一批：全部 16 个案例的离线契约与失败回归；U12 三个子案例单列。维护拟建 `backend/benchmarks/planner/cases.json`、runner 和初始化 fixtures；当前不存在可声称已运行的 runner。
- 第二批：常规组每案例 A/B 各 3 次真实 Planner + 冻结领域资料，记录每次结果，不用首个成功取代失败；AB/BA 交替，冷/热缓存分层，不混算。案例输入不能针对 B 暗中优化。
- 第三批：选择 U01、U02、U07、U08 小规模实时链路（各至少一次，条件/额度允许再重复），报价必须按新查询日期取得。报告实际样本数；Provider 不支持样本时保留失败/未运行原因。
- 初始付费执行串行；未形成单请求基线前不加负载。随后独立跑目标并发测试，避免把限流导致的慢归因于 Harness。
- 每批先确定可用凭证、调用上限与费用额度。历史 $5 或旧调用授权不自动作为新批次额度；未知费用保留未知，触及硬额度或频繁限流停止，不重置账本。
- C 仅在 A/B 评估批准进入试验后运行相同案例；先隔离/取消/协议适配门槛，再做 B/C 配对测量。锁定 DSH commit/依赖与最小工具集合，不默认加载编程工具。

## 4. 测量口径

每次保存 manifest：case/repetition/variant、开始时间、代码 SHA+dirty hash、工具/schema/prompt/fixture hash、请求与返回 model、Provider/路由、reasoning 最终出站值、token 限制、温度、缓存状态、并发、截止时间、预算；敏感凭据只记有无，不记值。

| 指标 | 定义 |
| --- | --- |
| T_ack | 同客户端点击至有效接单回执；不含单纯 loading 动画 |
| T_first_flight / T_first_guide | 同客户端点击至首个可查看/采用的航班或可浏览/修改的已保存攻略；分别报告草稿与已核验状态 |
| T_verified | 请求开始至服务器满足该任务验收并可恢复，不以模型声称完成计算 |
| T_final_ui | 同客户端点击至最终结果渲染；用户在多轮中的思考/选择时间另列，不计模型延迟 |
| 回合和返工 | Planner 请求数、工具调用数、外部 HTTP 数、供应商报告搜索数、引用/类型修复次数、错误触发的研究次数 |
| 成本 | 每轮 tokens 与已知费用，缺失 null；不把未知当零 |
| 质量 | 日期/预算口径/航班与来源硬约束 + 个性化、合理节奏、可操作性、表达清晰度 |

父工具 span 与研究模型子 span 不能相加；并行请求累计时长不等于墙钟时长。两端时钟未同步时不直接跨设备相减；端到端取客户端单调时钟，服务端时序独立分析。

质量由同一 rubric 对 A/B 匿名结果评审：四项软指标各 0–2 分，给具体理由；AI 审查与用户/人工复核单列，AI 自评分不能代替独立验收。硬错误（跨 owner、假来源/票价、预算范围反转、航班时间冲突、越权采用）直接失败，不被速度分抵消。

所有失败、取消、超时计入分母；超时记录 time-to-failure/截尾状态，不用 timeout 值冒充完成时间。缺测不算通过。报告逐案例、同类型中位数与范围；同一可比层样本不足 100 时不报告稳定 P95，绝不混合所有案例制造漂亮分位数。

### 4.1 当前 B5 取数与证据限制

服务端从默认 CloudPlanner 的 `plannerObservation` 结构化日志取每轮摘要（实现与字段见 [RUNTIME_PLAN §6](RUNTIME_PLAN.md)）。客户端从 `src/services/plannerTelemetry.ts` 导出的 `getPlannerTelemetrySnapshot()` 取当前进程有界快照；尚无产品导出入口或自动上传。用 accepted 的 generationId 加 Trip/conversation 关联两端，不能以两端时间戳相减。客户端 requestId 是本地序号，不等同后端请求 UUID。

T_ack 对应 clickToAckMs；T_first_flight/guide 当前代理值为 firstFlightCommitMs/firstGuideCommitMs，T_final_ui 为 finalUiCommitMs，均明确标记 effect commit 而非 paint。首结果必须来自本轮已发布且加载成功的可用卡片，保留验证状态；无点击的自动恢复不补造点击起点。时钟缺失、未出现该 UI 或终止前未提交均保留 null。timeToFailureMs 从 sendStartedAtMs 开始，不能混入点击延迟指标。组件 harness 测试不证明 H5/微信实际像素时间。

服务端 firstVerifiedMs 从 CloudPlanner runTurn 开始，止于 satisfied 持久提交，排除客户端网络/接单前等待；它与 firstGuideSavedMs 分开。modelUsage/modelCostUsdMicros 仅汇总模型调用，有任一未知则相应总计 null；knownModelCostUsdMicros 是已知小计，不能用作完整总费用。Provider 报告搜索数是有效 native 回执的小计，HTTP 数是适配器尝试数（不是工具数或供应商内部重试数）；失败正文也保留已知 native 计数。gateway 是适配器名，routeFingerprint 区分去敏后的入口，provider 只相信实际响应，没有响应不猜测。指纹不含消息正文，不能替代 manifest 的 prompt/fixture hash。

B5 不生成正式 manifest、案例 runner、缓存标签或分位数报告；这些仍属 G1 后的 M1/M2。后续批次必须收齐失败、取消、截断与未知样本，不能从当前离线回归推导提速比例。

## 5. 预注册评估门槛（目标，不是当前成绩）

### B 能否成为新主路径

- owner/版本/取消/引用等硬不变量回归全部通过；正常同口径用例不得出现预算语义反转或事实伪造。
- 常规测试组限时合格交付/正确澄清成功率目标 ≥90%，每个失败仍逐项解释；真实小样本只报告次数，不宣称总体可靠率。
- 完整证据的常规攻略目标约 2–3 次主模型调用；有新研究/局部修正单列，不用强截断回合换低质量。
- 首份可操作攻略目标约 15 秒，可用且满足验收的首版目标 30–45 秒；分别给冷/热证据表现，不能承诺每例达到。
- 与同口径 A 相比，B 完成时间中位数改善目标 ≥30%，或显著提高失败链路的合格交付次数且不损害交互；软质量均值不得下降，单案例不低于 6/8。小样本只作继续/调整方向信号，不宣称统计显著。

### 是否进入 DSH 试验，再是否迁移

| A/B 评估发现 | 决定 |
| --- | --- |
| B 达到质量和交互目标，维护成本可接受 | 暂不接 DSH，保存报告并继续现有 runtime |
| B 仍因引用/业务约束错误失败 | 修业务接口，不换框架掩盖 |
| 主要耗时是研究 Provider/模型响应，回合已合理 | 单独评估研究/模型/路由策略；不把换 Harness 当默认措施 |
| 残留问题可归因于通用上下文/工具协议/执行恢复或维护负担 | 进入小范围 DSH SDK 试验 C，先核实当前 SDK 能力 |
| C 同质量/隔离通过，配对中位时延再降 ≥20%，或重复证实减少失败/维护范围且首结果无明显退化 | 提出生产 runtime 替换 ADR，明确适配成本与回滚；不是自动上线 |
| C 收益不稳定、只换了默认模型才变快或边界不通过 | 保留 B，结束试验并记录原因 |

20%/30% 是提前固定的工程决策阈值，不是预计收益。修改阈值必须记录理由并重开批次，不能看完结果后移动门槛。
