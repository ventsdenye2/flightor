## 三阶段顺序

1. **现在：固定样例体验与展示数据整理**。旅行详情样稿的美术方向已获认可，其余界面已沿用统一规范实现。展示模型和样例组合已从页面中分离；不同目的地、部分结果与空数据通过同一套组件展示。里斯本沿用已选照片，京都缺图明确占位；新增页面的最终视觉意见、地图及微信端运行验收继续单独记录。
2. **随后：独立业务评测**。准备约 16 个代表请求，分别测试直接联网模型、冻结的当前体系、轻架构。单独记录研究与完整行程的质量、事实/约束满足、来源、耗时、成本及恢复。UI 美观度不计入模型评分。本轮未调用付费模型、未建立此评测分支、未产生评测成绩。
3. **最后：接口联调**。胜出业务结果通过普通转换函数接入统一展示模型，再验证真实结果、逐步返回与局部修改。当前 UI 分支不决定轻架构实验的旧提交基点。

## 展示数据消费契约

- `AppExperience({ trip, searchDataset, exploreItems, imageError? })` 是样例和页面之间的边界；`PlannerPage`、行程列表、收藏与详情消费同一 `TripPresentation`。替换来源应在入口组合或后续普通转换函数中完成，不能在页面加入 Provider/LLM 分支。
- `TripPresentation` 提供行程 ID、标题/目的地、日期范围与显示文字、天数/人数、封面、每日安排及完成状态、航班、候选活动与来源。`TripDay.id` 可为字符串或数字，按身份匹配；D1/D2 等序号取数组位置，不把 ID 当作序号或日期计算依据。
- 日程数据采用不可变快照。同 `trip.id` 收到新的 `trip.days` 数组引用时，用新快照替换本地日程，取消待执行的本地修改、关闭详情、清除撤销与旧提示；仍存在且已完成的选中日期保留，否则选择首个可查看日期。普通父组件重渲染而数组引用未变时，保留本地编辑。新的行程身份或入口切换整套样例会开启独立预览会话。
- 缺少图片、坐标、时刻、价格、日期或人数时显示相应待确认/占位，不补零、不借用默认里斯本数据。有效 `0` 价格/坐标与未知值分开处理；无坐标活动仍在列表中，无日程、无航班和空探索保留空态。部分日期只有已知的一端时仍展示已知范围。
- 价格同时保留金额、币种、按人/总计单位、示例/估算/未知状态及来源；航段保留未知时刻/时长。航班搜索自己的展示数据集负责条件匹配、排序与筛选，未知值不会变成最低价或最短时长。
- `scripts/check-ui-presentation.cjs` 与 `scripts/check-ui-flight-samples.cjs` 只加载纯展示数据模块，覆盖任意日期 ID、快照选中项、未知坐标/价格、候选去重、数据集匹配、筛选排序与空数据。它们不证明真实搜索、保存或地图服务可用。

## 运行

在本 worktree 下：

```powershell
npm --prefix apps/ui-preview ci
npm --prefix apps/ui-preview run dev
npm --prefix apps/ui-preview run build
npm run test:ui-experience:data
npm run check:ui-experience
npm run build:ui-experience
npm run check:ui-experience:weapp
npm run open:ui-experience
```

网页：`http://127.0.0.1:4178/`。网页产物在 `apps/ui-preview/dist/`；微信产物在 `dist/ui-experience/`。小程序编译复用本地已安装的 Taro 工具链，脚本也支持独立 checkout 自己的 node_modules。

`check:ui-experience:weapp` 检查独立产物文件、项目配置与开发者工具 CLI，并调用安装目录中的官方 `wcsc` 检查原生 WXSS 编译；`open:ui-experience` 请求本地 IDE 打开项目，不上传或发布。

本机旧 CLI 与正在运行的 GUI 使用不同的用户配置目录，现已解决：实际 GUI 使用 `TEMP/../微信开发者工具业务目录` 下的配置，辅助脚本自动识别其中已开启的 IDE 服务，不改安全设置。独立构建默认写入 `touristappid`，当前 IDE 拒绝该访客 AppID 时，可使用：

```powershell
node scripts/wechat-ui-check.cjs --open --project-appid
```

该选项只将仓库现有 AppID 写入 `dist/ui-experience` 的产物配置以供本地打开，不改源项目配置，也不上传或发布。官方 WXSS 编译实际发现了 `*` 通配选择器及 `> :first-child` 等隐式通配选择器不兼容的问题，相关样式已修复；类型检查和普通构建通过不能替代这一原生编译检查。
