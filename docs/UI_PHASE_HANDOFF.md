## 三阶段顺序

1. **现在：固定样例体验**。旅行详情样稿的美术方向已获认可，其余界面已沿用统一规范实现为完整交互样稿。UI 使用同一组照片与固定数据，避免把内容质量当成布局质量；新增页面的最终视觉意见、地图及微信端运行验收继续单独记录。
2. **随后：独立业务评测**。准备约 16 个代表请求，分别测试直接联网模型、冻结的当前体系、轻架构。单独记录研究与完整行程的质量、事实/约束满足、来源、耗时、成本及恢复。UI 美观度不计入模型评分。本轮未调用付费模型、未建立此评测分支、未产生评测成绩。
3. **最后：接口联调**。胜出业务结果通过普通转换函数接入统一展示模型，再验证真实结果、逐步返回与局部修改。当前 UI 分支不决定轻架构实验的旧提交基点。

## 本轮实际完成

- 主导航四页已连通：规划、探索、行程、我的。底部导航实际切换页面；网页控制台另提供八个页面直达入口，微信独立入口复用同一 `AppExperience`。

- 航班：出发地/目的地交换、日期与人数、表单校验、加载/取消/失败重试、固定结果与无匹配状态；排序、筛选草稿与应用、最多两个候选比较、航段详情和目标价格提醒。当前仅 `PVG → LIS`、`2026-10-12` 有固定样例，其他条件保留无匹配反馈。
- 行程列表：待出发/已归档切换、打开详情、归档与恢复、新建规划。新建会开启空白输入；普通栏目切换保留已有规划会话。
- 白底、海洋青、目的地衬线标题的旅行详情保留概览、每日行程、航班三视图。
- 上海—多哈—里斯本 7 日固定示例；复杂中转场景增加马德里，显示三航段和自行中转注意事项。
- 日期选择、地图编号与活动列表一致；两处点击均打开同一活动详情。
- 固定候选替换、移出、撤销、减少最后一个停留、添加观景台、空白日、局部调整中反馈。
- 收藏页：全部/灵感/行程筛选、空态、打开收藏内容、取消收藏与撤销；探索书签、行程书签和“我的”数量使用同一份共享状态。

- 收藏、提醒、偏好与演示账户只在本次预览会话生效，刷新/重置清除；没有真实登录、云端保存、保存冲突或真实持久化验收。

## 视觉核对

用户于 2026-09-13 确认：“我觉得可以，其他界面的UI应该遵循相同的美术风格”。因此白底、海洋青、衬线内容标题、实景图片及现有组件语言成为后续页面的共同基线；页面布局按信息量与任务调整。

旅行详情已对照上一任务生成的概念图及实际手机截图检查：白底与海洋青、目的地标题层级、实景首图、票卡时间对齐、底部导航、底部活动详情与双操作按钮。新增界面共用这套颜色、标题、卡片、按钮和弹层；规划保留简洁输入与对话，探索延续实景与杂志排版，航班和设置按信息密度组织表单与列表。

真实授权照片替代概念中的生成照片；网络失败时展示事实性的地图降级。用户对美术方向的认可不等于新增每页的最终验收，也不得据此宣称地图视觉或微信端达到最终设计验收。

本轮按已认可的旅行详情参考逐项检查了新增页面：

| 核对点 | 实际结果 |
| --- | --- |
| 配色 | 页面保持真白底、深墨色标题、海洋青操作和浅色分组，无新增渐变或照片蒙色 |
| 字体 | 主要内容标题延续中文衬线，表单/导航/正文使用 sans，时刻与价格对齐；修正共用输入样式覆盖机场大字号的问题 |
| 图片 | 使用同组本地实景资产，详情可重试；氛围参考和来源待复核信息保留 |
| 组件 | 卡片、线性图标、按钮与 22px 顶部圆角弹层沿用共同规则；修正弹层双按钮间距和导航遮挡 |
| 页面布局 | 规划为简洁输入与对话，探索为图片与主题，搜索为表单/票卡/比较表，我的为列表；这是用户要求的跨页扩展，不机械复制旅行详情首图 |
| 文案与状态 | 保留中文主导航和明确操作；移除新增首页的无用途英文前标题，显示示例/未知/失败/撤销，不声称真实生成或保存 |
