# 模型与后端研究架构：首轮结果

日期：2026-09-13（Asia/Shanghai）。实验分支：`codex/model-architecture-lab`。本轮仅覆盖活动研究组件，未修改主仓、前端工作区或生产模型配置。

## 结论的适用范围

用户要求避开 Anthropic、Google、OpenAI 模型后，本轮改用当前账户实际调用成功的 Qwen、GLM、Kimi、DeepSeek。可用性结论只代表本机、当前账户和本次 OpenRouter 路由；不能扩展成所有中国地区账户的可用性保证。MiniMax M3 实测 403，未纳入正式评测。

本轮的后端方向是让研究能力成为可替换的小服务：模型负责检索和候选生成，普通函数负责可审计的结构转换与校验，领域服务继续拥有来源状态、持久化、取消、版本与交付验证。可解析 JSON 不能替代事实核验，研究组件返回也不能替代完整行程交付。

下一阶段优先验证 **Qwen 3.8 Flash 与 GLM 5.3 Flash**：本轮两者经普通函数转换后均为 15/16 契约通过，Qwen 的研究调用中位数较低，GLM 的原始契约通过率较高。Kimi 的剩余失败较多；DeepSeek 的联网结构化组只完成两例便出现长耗时和超时，证据不足以给完整模型排名。上述选择是进入后续验证的候选，不是生产切换决定。

## 同一联网方案的模型对比

下表使用 v3、并发 2、Exa 的正式样本。原始契约允许完整 JSON 或完整 JSON 围栏；前后夹说明文字不算原始通过。费用是该组真实响应的 `usage.cost` 总和，包含模型及网关报告的搜索费用。

| 模型 | 案例数 | 原始契约通过 | 普通函数转换后通过 | 调用中位数 | 已知 API 费用合计 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Qwen 3.8 Flash | 16 | 10/16，62.5% | 15/16，93.8% | 20.25 秒 | $0.249591 |
| GLM 5.3 Flash | 16 | 13/16，81.3% | 15/16，93.8% | 25.31 秒 | $0.213742 |
| Kimi K2.6 | 16 | 4/16，25.0% | 10/16，62.5% | 19.28 秒 | $0.269594 |
| DeepSeek V4 Flash 0731 | 2 | 0/2 | 1/2 | 79.54 秒 | $0.014526，另 1 次未知回执 |

前三个模型各有 16 次 HTTP 成功返回，结构失败保留在分母；成功返回并不保证回答完整或事实可靠。DeepSeek 的 2 例与其余模型覆盖不相同，不能直接比较中位数或通过率。全部模型每案例仅一次，不能据此估计稳定胜率。

## 同一模型的后端对照

以下两组均为 DeepSeek V4 Flash 0731，16 个案例各尝试一次。thin-web 的 DeepSeek 组只有两例，三架构对比尚未形成完整的 16 × 3 矩阵。

| 方案 | 已尝试 | 运行结果 | 调用中位数，含失败 | 已知 OpenRouter 合计 |
| --- | ---: | --- | ---: | ---: |
| 直接联网回答 | 16 | 14 次返回文本，2 次 95 秒超时 | 22.72 秒 | $0.186590，另 2 次未知回执 |
| 现有研究组件 | 16 | 5 次正常返回，11 次部分结果；8 次 artifact 非空 | 30.02 秒 | $0.000639 |

现有组件共派发 23 次 SerpApi 请求，其中 11 次失败；成功执行综合的 8 次中位耗时为 9.10 秒。一次活动研究因并发对照出现未知账单，被实验公共预算停止综合，随后走现有组件降级逻辑；该样本 `architecture-baseline-v3/sample-011` 不能解释成 Provider 自身的综合失败。已派发搜索保留，未重跑该格。

现有组件的 16 个 artifact 均满足它自己的领域结构，但其中一半为空；这与薄后端的 JSON 通过率不是同一指标。澄清类案例允许没有候选，且现有组件没有对话澄清能力。因此非空率也不是内容正确率。8 个非空 artifact 共 42 项，包含降级候选及未核实来源，不能当作 42 个有效活动。

本次观测支持进一步简化研究 Provider，但不证明完整后端会从 150 秒降至 20 秒。搜索缓存、路由、两格并发、模型提示和搜索引擎均有影响；没有测首 token、首个有用结果或完整 Planner 交付时间。

## 实验协议与证据

以 [cases.json](../../experiments/travel-research/cases.json) 中 16 个中文案例作为统一输入，覆盖常规城市研究、带娃、轮椅、过敏、季节日期、预算、多城市、转机、缺失信息及虚构活动。每格一次；随机顺序使用固定种子；最多两格并发。此次不估计 p95、方差或统计显著性。

- `thin-web`：联网模型返回结构化活动候选；统一 Exa server tool，最多两次搜索，最多十条检索结果，输出上限 3200 token。
- `direct-web`：相同研究输入和联网能力，返回可读文本；不要求 JSON。
- `current-system`：冻结主仓当前实际 `ProductionResearchAgent`、SerpApi Provider、综合模型和领域验证实现，包括未提交的后端修改；当前综合仍使用原有 4000 token 上限。

当前实现只接收 ResearchBrief，而 direct/thin 还接收原始用户请求；当前实现没有对话澄清 disposition。这是产品组件边界差异，不能把相关差异归为模型能力。SerpApi 与 Exa 的检索内容也不同，架构比较同时包含搜索来源差异。

正式协议为 `research-v3-aligned-contract-routing`：类别与数量按案例约束，API schema 与提示共享定义，允许同一模型在可用 Provider 间 fallback。GLM 需要 low reasoning；其余模型请求关闭 reasoning。具体参数和实际回执保存在各批 manifest 与 sample 中。

旧 pilot、v2、可用性探测全部保留，分组列出，不并入 v3 正式指标。早期已发现并修正了提示合同不完整、类别范围和对照结果投影丢失警告的问题；不能把协议变化后的差异解释为单一模型改善。

## 结构转换实验

[normalization.mjs](../../experiments/travel-research/normalization.mjs) 对原始回答做离线回放，单独报告转换前后结果。允许的操作只有：提取无歧义的末尾 JSON、去除合同外字段。所有操作都有记录；不填缺失字段、不改类别、不补来源、不裁剪超量候选，也不修改日期与事实。

这项消融不再调用模型，不增加 API 费用。转换后通过不能倒算成模型原始通过，也不能证明对应事实正确；转换是在看过本轮失败后设计，存在适配当前样本的偏差，必须用后续新案例复验。

## 内容与架构发现

详细逐条记录见 [来源抽查](quality-spot-checks.md)。这是 AI 执行的来源抽查，不是全量人类盲评；[100 分人工量表](../../experiments/travel-research/rubric.md) 尚未填写，当前不发布内容总分或生产模型冠军。

当前架构没有在活动研究路径额外调用 query-planner 模型，而是并行搜索后进行一次综合。因此，仅删除一个假想的模型步骤不会解决延迟问题。应分别观察搜索、综合、整个研究调用的时间，以及工具返回到最终用户交付之间的时间；本轮只测到研究组件。

片段来源可导致通用目录被当作活动、日期断言超出片段支持。当前领域 artifact 会保留 `unverified` 等警告，呈现层必须继续保留。联网模型的引用也可能关联到 URL 而没有支撑具体主张；任何方案都需要可追溯的证据边界。

## 下一阶段实施边界

1. 保留 `ResearchBrief → ResearchArtifact` 作为领域接口，允许替换内部研究 Provider。联网搜索和模型格式差异留在 Provider 适配器内。
2. 以普通函数做结构转换，再校验目标、日期范围、来源关联和结果数量；保留原始回答、转换记录及未核实状态。转换失败明确返回部分结果或错误，不自动增加修复模型调用。
3. 在同一 Planner 下接入候选 Provider，验证取消、超时、保存、恢复及 server-verified delivery，并记录首个有用结果与完整交付时间。完成这些验证后，才决定生产默认模型和是否替换现有研究实现。

本轮交付的是独立实验工具、真实 API 回执、可复现输入与报告；尚未将实验适配器接入生产服务。

## 费用、覆盖与验证

共保存 **106 条样本记录**，包括探测、旧协议和失败；正式 v3 为 **82 格**：Qwen/GLM/Kimi 各 16 格 thin-web，DeepSeek 2 格 thin-web、16 格 direct-web、16 格 current-system。原 96 格筛选计划剩余 14 格 DeepSeek thin-web 未执行，原因是该组合前序格式失败和长耗时；没有用其他模型结果补齐。

截至 2026-09-13 03:06 左右的 OpenRouter 当日 key usage 核对，保守累计已知消费为 **$1.197637**；另保留 **$2.25** 未知调用预留，合计占用准入预算 **$3.447637 / $5**。预留不是已花费用，也没有从账本释放。key usage 可能包含同一 key 的其他任务，因此不声称全数精确归属于本实验。超时缺少 generation ID，无法逐笔核对，最终以供应商账单为准。

SerpApi 只读账户回执确认当前为 Free Plan、月费 $0；后端补齐前剩 108 次，结束后剩 95 次，未购买或升级套餐。实验累计派发次数单独保留，不能把请求次数、实际扣减额度及美元账单混为一项。参见 [Account API 官方说明](https://serpapi.com/account-api) 与 [脱敏账户回执](../../experiments/travel-research/results/2026-09-13/receipts/serpapi-account-after-baseline.json)。

三个正式后端快照逐份核对 287 个文件，SHA-256 均无差异；各 v3 批次的 casesHash、modelsHash 与四个请求关键代码摘要一致。共享的已安装 node_modules 通过 junction 使用，依赖锁文件已记录，但不是完整依赖字节快照。

收尾全套离线测试 **45/45 通过**，覆盖真实后端适配器的 mock Provider 运行、失败降级、取消与已派发调用记账、引用和多城市投影、机械转换、费用准入、锁竞争及续跑一致性。测试未产生模型费用，不能替代真实 Planner E2E。另对实验及快照的 2534 个文本文件检查实际密钥值，未发现泄漏。

收尾审查补强了未知账单下的搜索准入、账本字段校验、核对锁、截断状态优先级及续跑配置一致性。现有真实账本字段有效，未发现截断状态被误报或 v3 混基线；这些修正针对潜在缺口，不声称本轮已发生费用失控。修订后的 runner 标为 **v4，仅离线验证，未新增付费样本**。新增文本长度 schema 限制也只适用于后续 v4 请求；v3 原始回执未改写。
