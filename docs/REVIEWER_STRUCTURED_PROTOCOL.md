# Reviewer 结构化工具交付

更新：2026-10-26。状态：已接入；后端离线回归 100/100 通过，真实模型使用旧失败任务同一输入复测通过（1 次首轮结构化提交，无补正）。

## 当前协议

Reviewer 不再通过最终 assistant 正文交付 JSON。它在同一 DSH Session 中先按需调用 `lookup_places_batch`，再调用 `submit_itinerary` 一次，参数 `itinerary` 为完整结构化行程对象。工具成功后可以结束本轮；不再把同一对象写进正文。

`submit_itinerary` 只注册给 reviewer。参数 schema 固定标题、目的地、概览、亮点、每日活动、航班选择和 issues 等结构；活动继续保留与地点补全相同的 `id`。工具结果只返回 requestId、接受状态及天数/活动数，不把大型对象再回传模型，避免额外输出和上下文开销。

后端只从本次执行窗口内、按 `toolCallId` 配对且带有当前 requestId 的成功工具参数读取行程。相同对象重复提交按幂等处理，不同对象视为协议冲突；取消、旧请求、迟到结果和 assistant 正文都不能发布。

## 失败与耗时

首次工具提交成功时不增加模型回合，因此正常路径不增加计划外的生成等待。工具参数在 DSH 原生层校验失败时，具体错误直接进入原 Session；如果模型没有提交工具，应用层才在同一 Session 追加一次明确提醒。首次交付和补正最多一次、补正最长 30 秒，并受原任务超时与取消信号约束。补正期间 native guard 只允许 `submit_itinerary`，禁止重新景点查询、搜索或查票。

补正仍失败时，任务以 `OUTPUT_PROTOCOL_ERROR` 结束并保留 `reviewProtocol` 诊断，不把正文当行程、不生成空行程冒充成功。HTTP 与前端接口形状保持不变。
