# 双 DSH Agent 最小接入

2026-10-19。用户要求在当前 backend-mvp 原目录，用本机已安装的最新版 DSH 验证规划 / 审核两个独立 Agent；保留非界面插件，通过现有 trip-flight-tool CLI 查询航班。当前核心链路已实现，最终平台验收见本文结果表。

已读取用户指定网页对话除最后一组问答之外的四组内容。采用独立上下文、审核者读取原始需求和工具结果的自动接线。按用户后续明确要求，MVP取消业务校验、审核否决和自动返工，先跑通再说；不采用最后一组手工复制两个会话的操作。不恢复旧 D6 后端或裁剪后的 runtime。

`backend/scripts/copy-dsh.mjs` 从已安装桌面程序的 ASAR 中提取完整 dsh 分发包到忽略的 `backend/.dsh-runtime/`，记录版本、源归档 SHA256 和文件数。原安装、用户账户和默认插件配置不改。仅运行时 profile 排除图形界面和外观插件，组成见下文。复制包不是 Git 源文件；换机器需重新执行复制命令。

## 架构与校验范围

用户原文 → DSH规划会话（自然语言 + 工具）→ DSH审核整理会话（原文 + 草稿 + 原始工具结果）→ 展示适配 → JSON保存 → H5/微信共享页面。两角色是两个独立DSH子进程，各有自己的session/workspace，不是在一个会话中自称两个角色。

审核JSON只承载行程业务字段；内部ID、来源对象和真实机票字段由代码组装。不检查天数、日期、日序、来源完整性或业务约束是否通过，不设人数/活动上限。缺字段使用展示空值；非JSON返回以原文概述展示，不因格式拒绝。资料不足和审核意见随概述展示，来源保持unverified，不将链接展示当成事实验证。未知坐标留空。航班卡片读取CLI快照，查询时间和历史状态仅作说明，不是输出门槛。

协调器不执行返工，不因审核意见拒绝输出。信息缺失时规划者直接给初稿并说明假设，不等待资料补全。工具注册清单仅记录诊断，不作为启动门槛。旧报价比较案例是开发者自设的CLI读取测试，不是用户业务要求。最终结果保存后公开completed；取消、进程调用失败、磁盘写入失败仍按实际执行状态记录，不伪称成功。没有旧Planner、旧终稿模型或多层修复。

当前实现接线：两个独立 SDK 子进程，各自独立 session/workspace；规划草稿和原始工具结果由薄协调函数自动交审核者并直接展示。根 API 只监听127.0.0.1:3000，POST /api/runs、GET/DELETE /api/runs/:id，结果保存在忽略的 backend/data，未引入旧后端/数据库/任务队列。H5 /api 通过Vite转发；小程序通过Taro.request访问本机地址，可用storage `flightor-api-base-url`配置设备可访问的后端。两端只保存最近一次成功runId，刷新通过只读GET恢复结果。

模型沿用桌面 profile 的 deepseek-account / deepseek-flash；凭证插件引用原 ~/.dsh/.credentials.yaml，密钥不复制，不进入前端，不覆盖思考强度和模型默认输出上限。运行profile保留完整base、SDK、auto-review、可选持久终端、Codex子agent扩展与市场host服务；没有工具白名单裁剪。工作区依赖与Office插件继续引用桌面配套运行环境。不运行任何界面、启动屏、壁纸或宠物插件。DSH的SDK官方配置本身会关闭界面不需要的标题生成和HMR；不是删除插件。插件能挂载和工具能注册不等于逐一验收了所有插件功能。

## 本机包和命令

- 运行包：桌面内置0.2.1-rc.2；不是PATH里的0.1.1-rc.2，也不是未构建的源码alpha分支。
- 源归档SHA256：47874618bf5b3011fcaac10cd4c85f69da333e70d4f99b921207c78d0999512a。
- 原始副本17,262文件，配套Node24.21.0另复制；外置Codex子agent及其CLI依赖本地复制。版本/组成记录在 backend/dsh-inventory.json。
- npm run backend:setup / backend:start / backend:test / backend:live。首次复制由backend/scripts/copy-dsh.mjs完成，副本已存在时不覆盖。prepare-dsh生成本项目隔离profile和模块junction，不改用户默认profile。
- search_flights调用 `node trip-flight-tool/dist/cli.js search`；get_flight_details调用其details命令。所有参数经argv传递，无shell字符串拼接。CLI本身的重试、访问限制与证据保持原样。
