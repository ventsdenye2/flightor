# 景点图片与行程内容

更新：2026-10-19。适用于当前 `backend-mvp`，不沿用旧后端的媒体服务或发布流程。

景点获取机制已更新为 [统一 PlaceResolver](PLACE_RESOLVER.md)：本地索引确定 QID/坐标，线上补多语言信息，图片以 P18 和同 QID 主图优先；缓存/超时/API 来源以该文档为当前合同。下文旧版独立名称搜索和原验收保留其历史范围。页面位置、数据字段和展示交互保持不变。

## 内容分工与 JSON

### 概览展示范围（2026-10-19调整）

概览仅保留图片封面（含必要署名/许可）、“这趟旅行，值得期待”、 “出发前留意”和世界航线图。删除D1–Dn预览、行程长摘要、重复标题/日期/人数、报价/航班卡、城市景点地图、旧路线示意及概览底部说明。每日安排和完整航班信息仍在各自标签页；数据与Agent JSON不因此次界面精简删除。缺少亮点或提醒时不以旧长摘要补位。

世界图采用本地Natural Earth 1:110m陆地轮廓（公有领域），经纬度等距投影与相同投影的机场点叠加。坐标来自已有机场目录相同的airportsdata固定版本`47ae282a8491758e6dafe28d4139539e561b54d5`，7884个IATA机场，MIT许可；不编造位置，不调用地理编码或地图瓦片。首组已保存航班的有效航段按大圆插值绘制，飞机依次飞过；跨180度边界时拆线，未知机场/无航班只显示世界底图。动画为航线示意，不表示实时位置或实际飞行轨迹。

提供暂停/播放，H5系统减少动态效果时停止动画；切换标签页卸载动画。两端共享View/Image实现，不依赖SVG内嵌动画。数据来源/哈希为`src/assets/ui-experience/world-flight-sources.json`，原机场许可随资产保存。离线重建：`node scripts/generate-world-flight-assets.cjs <Natural Earth land.geojson> <固定版本airports.csv>`；生成器复用trip-flight-tool的csv-parse依赖，不在页面运行时下载数据。

本批验证：`npm test`、`npm run check`、`npm run build`通过；新增几何回归覆盖真实机场查找、未知机场留空、起终点、有效坐标与跨180度边界拆线。微信构建有原有图片体积/分包建议，因新增机场坐标，页面脚本386KiB也超过webpack建议244KiB，构建仍成功。

Browser plugin not available，独立Chrome/Playwright CLI在`127.0.0.1:4178`使用当前真实9天行程验收：概览恰有四个内容区域，无每日预览、摘要、报价/航班卡、景点地图、旧路线图和底部说明；封面可解码，页面标题/非空/无框架遮罩、控制台错误和警告均正常。飞机位置随时间变化，暂停后保持位置，减少动态效果时停用移动；320/390宽度无溢出且地图投影宽高比保持2:1。每日标签仍有9天，D3详情可打开，航班标签仍有完整票卡。截图检查涵盖1440×1000与390×844。当前保存行程的结构化航段为返程PRG→MXP→XIY→PKX，图按这些真实方向显示，未反转成未经保存的去程。未调用付费模型/机票供应商，未做微信真机验收；此前记录仍只对应原版概览。

规划 Agent 先搜集必要旅行资料，逐个景点提供介绍、推荐理由、游玩安排，以及能明确对应的英文/当地名称和所在城市。审核 Agent 只从草稿、用户需求和已有工具结果筛选有价值的信息，不重新查询、不拒绝输出、不要求返工。

- `overview`：约80至160字，提炼旅行体验、路线顺序和节奏；不复述聊天或堆砌航班与风险。
- `highlights: [{title, description}]`：少量具体、与用户需求相关的旅行亮点，信息不足可为空。
- `issues: [{detail}]`：重要待确认事项，映射为展示层 `travelNotes`，单独显示“出发前留意”，不再拼进概述。
- 景点的 `description` 映射日程列表 `summary`；`introduction`、`recommendationReason`、`visitNotes` 分别显示“关于这里”“为什么安排这里”“游玩提醒”，另有“怎么玩”。不编造用户兴趣、历史、价格和开放时间；无依据可留空。
- `imageQuery` 是明确单个景点的英文/当地名称，`city` 为其所在城市；组合活动选择其中一个代表，泛称、交通或自由时间设 `imageQuery: null`。审核结果不接受模型提供的图片URL。

旧行程不会因提示词变化自动改写文字。缺少新字段时继续显示旧摘要；若要新的介绍、推荐理由和概览，需要重新生成行程。旧景点仍会尝试以原名称查询照片，中文或多景点组合名称可能没有精确结果。

## 每日景点地图（2026-10-19）

每日地图固定在当天标题/日期下方、具体活动列表上方，沿用H5 Leaflet/OpenStreetMap及微信原生Map。已有有效坐标直接显示；缺坐标时，仅对用户当前打开日期的明确景点按名称/已有`imageQuery`与城市查询Wikidata，使用P625的地球坐标。名称、城市、唯一实体及有效坐标需匹配；同名歧义、城市不符、绘画、无坐标或冲突位置保留空缺，不用城市中心或示例点冒充景点。街道检索可去掉英文Street/Road/Avenue后缀，仍要求同名同城。

`POST /api/place-locations`接收`{name,query?,city}`，返回`{status:resolved|not-found|unavailable,location:null|{latitude,longitude,source}}`。固定查询Wikidata Action API，不调用Agent/付费地图、不创建run，不重写历史行程。只发地点名与城市，不发送聊天。实体来源链接随结果保留；成功缓存30天、无匹配缓存1天、网络失败不缓存，同请求合并，单次查询整体12秒超时，429后暂缓调用。每个日期串行查询，切换日期时忽略旧结果并停止继续查询；异步定位不重置打开的景点详情。照片查询与地点定位独立。

地图编号沿用原活动序号，连线仅连接已取得坐标的地点、表达游览顺序，不作为道路导航。点击标记打开同一编号景点详情；部分地点未知时保留已知标记，全部未知时保留地图位置并说明待定位。H5地图以地理场景内容识别更新，照片/文字变化及打开详情不会触发重新居中。地图数据来自[OpenStreetMap](https://www.openstreetmap.org/copyright)，坐标来自[Wikidata数据接口](https://www.wikidata.org/wiki/Wikidata:Data_access)及[P625](https://www.wikidata.org/wiki/Property:P625)。

本批验证：后端27/27、`npm test`、双端类型检查与两端构建通过，H5地图最终适配后再次类型检查/H5构建通过。保留H5包体、微信脚本/图片体积及分包建议。真实Wikidata请求取得布拉格城堡Q193369、聂鲁达街Q1054194、查理大桥Q204871的坐标并缓存；后端已重启，代理健康接口ready。

Browser plugin not available，独立Chrome/Playwright CLI使用真实保存的D3行程，在1440×1000、390×844及320宽度验证地图位于标题/日期与活动列表之间，真实OSM瓦片已加载，标记1/2/3与原序号一致，点击查理大桥标记打开同名详情，关闭后保持D3与地图视口，刷新恢复三个点。延迟D3定位并切到D1后，旧结果不混入D1；320/390无横向溢出。页面身份、非空、无框架遮罩、控制台错误/警告均正常，截图已检查。分批坐标返回时曾发现Leaflet缩放动画使后一次fitBounds丢失、标记超出视口，已改为立即应用场景边界；标记鼠标/键盘直接适配共享事件，关闭焦点自动平移。未调用付费模型/机票接口，未做微信模拟器或真机验收，历史行程和原始证据未改写。

## Commons 图片链路

`POST /api/place-media` 接收 `{name, query?, city?}`，只向固定的 Commons Action API 发起名称搜索与 `imageinfo` 查询，返回 `{status: ready|not-found|unavailable, media: object|null}`。该接口不创建run、不调用DSH、不查询机票，不受规划单并发占用；错误输入返回400，过大输入返回413。图片匹配本身不是新的业务验收门槛。

展示字段包含 API 返回的缩略图 URL、景点名、作者、Commons 文件页、许可名称和链接。仅接收 Commons 的 HTTPS 缩略图主机 `upload.wikimedia.org` / `thumb.wikimedia.org`，与景点名称相符的足尺寸 JPEG/PNG/WebP，以及明确的 CC BY、CC BY-SA、CC0 或公有领域记录。缺许可、无作者、受限、模糊匹配或查询失败时留空，不借其他景点或样例照片。不能保证任意命名的景点都有图片，也不能把文件名匹配说成实地人工核对。

H5与微信在打开真实行程后独立异步请求，每个视图最多两条并行；文字先显示，图片补全不重置选中日期或打开的详情。首个取得图片的实际景点可作为概览配图，标注其名称。详情、概览及“图片与来源”提供作者、来源和许可入口；微信复制外链。图片文件由客户端直接从 Wikimedia 加载，后端仅缓存元数据。

成功记录在忽略的 `backend/data/place-media/` 缓存7天，无匹配结果缓存1小时，网络失败不缓存；同一名称/查询/城市的并发请求合并。重启后继续使用缓存，不改写历史run或原始证据。undici 读取现有 `HTTP_PROXY` / `HTTPS_PROXY` / `NO_PROXY`，不修改系统代理。单次外部查询10秒超时；断网不影响文字和规划。

API与元数据依据：[Commons API](https://commons.wikimedia.org/wiki/Commons:API/MediaWiki)、[Imageinfo](https://www.mediawiki.org/wiki/API:Imageinfo)、[undici 环境代理](https://github.com/nodejs/undici/blob/main/docs/docs/api/EnvHttpProxyAgent.md)。
