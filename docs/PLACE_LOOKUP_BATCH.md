# 审核 Session 批量补全地点

更新：2026-10-20。当前查询顺序实测完成，审核工具/后端合并已接入；补全预算现按景点数量计算。下述结果与[原严格策略验收](PLACE_RESOLVER_ACCEPTANCE.md)分开记录。

## 需求与设计

- P1：MVP 优先覆盖与耗时。坐标只要求合法经纬度；图片保留可用 Wikimedia 图片、作者、自由许可与来源，不要求图片、坐标或名称的 QID 严格一致。
- P2：审核者在已有 DSH Session 调用 `lookup_places_batch`，一次传全部有代表景点的活动，活动使用稳定 `id`。后台保存实际结果；工具只返回 `found/not-found/unavailable/timed-out` 等字段状态，不让模型抄写 URL 和坐标。
- P3：成功字段锁定。明确 `not-found` 的字段可由同一审核者改写搜索词一次；第二次仍缺失留空。超时、429、5xx、网络故障由运输层重试或数据源回退，不计为语义失败，不允许触发关键词改写。
- P4：补全默认共享预算为“首次批量调用的景点数量 × 2 秒 + 5 秒”；按唯一活动 ID 计数，图片/坐标两个字段不重复计数，无景点为5秒，6景点17秒、16景点37秒、36景点77秒。从第一次批量调用开始，后续缺失字段修正、恢复账本或补交活动不重置/扩充截止时间。可用后端环境变量覆盖为固定预算；工具外层不再另设旧固定超时，由批量账本控制动态截止时间及取消。预算内完成的字段即时保存，超时保留部分结果，不阻止发布。审核者原有整理/最终 JSON 生成时间属于审核，不含在网络补全预算内；协调器仅调用一次 `reviewer.run`，不新建 Agent。DSH 在工具返回后仍需模型正常续写，不能理解为整个工具循环只耗一次模型推理。
- P5：后端依最终活动 ID 合并到 `TripPresentation` 并保存。新结果带 `placesResolved` 标志；前端正常加载该结果不调用地点接口。历史结果与手动/兼容接口保留。

允许修改审核工具插件、提示词、协调器、地点查询服务和展示数据加载；不改三 Agent 拓扑、航班查询与地图渲染组件。模型提供的图片 URL 不可信，实际图片仍来自查询服务。

## 实施与验收计划

1. 建立覆盖优先的独立字段查询，保留现有严格解析作为历史比较；验证坐标与图片互不阻塞、自由许可过滤保留。
2. 建立后端批量账本和工具，验证 ID、成功锁定、一次语义改写、网络错误分类、总预算与部分结果、取消。
3. 同 Session 工具接入审核，按 ID 合并结果并保存；前端新结果关闭自动补查，历史兼容。
4. 后端/前端回归、双端类型与构建；真实 Wikimedia 批量样本、浏览器已合并数据展示与零地点请求验证。真实模型调用与假执行器回归分开记录。

## 不合并 HTTP 请求的路径实测

数据目录：`backend/data/place-batch-benchmark/priority-path-v1/`（忽略）。36 个真实景点，沿用原固定清单的中文/英文/同名/小众分组，但此次显式提供固定英文/当地搜索名，城市仍单独传入，模拟审核者已整理搜索词。搜索名使用清单已有 `referenceTitle`，没有传参考 QID 或坐标。没有模型参与本轮批测，没有语义修正；不能和上一轮“仅名称+城市”逐景点测试作严格耗时/准确率对比。
