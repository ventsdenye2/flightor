# 当前上下文：双 DSH Agent MVP

更新：2026-10-19。

## 当前实现

- 逐日规划提示词新增[抵达依据前提](FLIGHT_OPTIONS.md)：有已选/采用的航班组合或可用已购航班信息，或用户明确告知抵达时间后再安排；否则在用户要求规划时用现有航班工具查询，缺参数先询问。查询后让用户选择完整航班组合，抵达时间从组合读取；不让用户仅选抵达时间，不擅自选择候选。这是提示词约束，保留现有接口/按钮协调器，没有新增代码硬拦截。

- 景点当前采用[审核 Session 批量补全](PLACE_LOOKUP_BATCH.md)：本地索引和缓存 → Enterprise → 公共 API，覆盖优先，合法坐标和具备自由许可/作者/来源的图片查到即保留。审核者在当前 DSH Session 用 `lookup_places_batch` 一次传全部景点，只对明确未找到的字段修改关键词一次；成功字段锁定，超时/429不触发语义改写。后端按活动 ID 合并 `TripPresentation`，20秒共享查询预算到期保留部分结果，三 Agent 拓扑不变。

- 每日景点地图位于当天标题/日期和活动列表之间；新行程直接使用后台附带的坐标，`placesResolved: true` 的缺失字段不在打开页面后自动补查。旧记录继续兼容地点接口。标记沿用游览编号，可打开详情，见[每日地图](TRIP_CONTENT.md)。
- 行程概览按用户要求只保留封面、旅行亮点、出发前提醒和动态世界航线图；每日D1–Dn及航班详情保留独立标签页，不在概览重复。世界图使用本地真实地理与机场坐标资产，未知航段不补造，见[展示范围](TRIP_CONTENT.md)。
- 新行程图片在审核期间由后端查询并合并，保留 Commons 作者、许可和来源；旧记录仍可通过[兼容接口](TRIP_CONTENT.md)异步补全。规划与审核分别保留介绍、推荐理由和游玩提醒，概览提炼体验与亮点，关键待确认事项单列。旧行程文字保留，新行为需重新生成。
- 对话中的航班选项与行程入口按产生它们的助手消息保存和显示，新消息接在后面；刷新恢复该对话的已生成行程。航班选定后发送下一条消息即锁定旧组选项，后续聊天不会将它移到列表底部；新查询可建立新组选项。
- 行程入口采用浅蓝底、蓝色边线、日历图标和宋体标题的独立结果卡片，蓝色“查看行程”入口与航班选择按钮呼应；整张卡片可点击，长标题换行，位置仍跟随对应对话消息。

- 对话中的真实 CLI 查询可显示[可选航班卡片](FLIGHT_OPTIONS.md)，支持票价/时长比较、推荐理由、航段与行李详情；选择只保存偏好，点击规划或明确表达开始规划时才使用对话上下文和选定航班生成行程。

- 前端更新为 `codex/demo-v2` 视频工作树的新版共享样式、图标、欢迎页、旅行详情与航班卡片，按当前 MVP 接口适配；同步来源和验证见 [FRONTEND_SYNC](FRONTEND_SYNC.md)。H5 仍使用 Leaflet + OpenStreetMap，未引入视频离线示意地图或旧后端发布门槛。

- 规划页新增持续自然对话：默认发送消息不直接启动原规划任务；DSH根据最后一条用户消息与上下文判断明确的制作行程意图，才自动进入规划。用户也可点击独立“生成行程”。对话ID存双端storage，公开消息存本地conversations，刷新恢复；生成使用完整带角色对话。输入框在聊天后继续保留。
- 对话输入框删除底部固定提示“想法、问题、偏好，都可以聊聊”；发送/停止按钮继续靠右，仅恢复历史时显示临时加载状态。该精简同步作用于H5与微信共享组件。
- 聊天状态只展示最新一条DSH实际活动摘要（会话、工具、重试、保存等），不公开内部推理。运行时发送按钮变为停止图标；取消立即退出等待，迟到消息不覆盖新对话。H5单次HTTP请求20秒超时，避免网络无响应时无限显示忙碌。完成后提供查看行程；恢复记录失败显示错误。UI沿用原有规划页样式，不在每次发消息后跳走。

- 小程序入口：`apps/ui-preview/taro-entry/`，Taro 3.6 / React。
- H5 入口：`apps/ui-preview/src/main.tsx`，Vite / React。
- 共享 UI、展示类型和样例：`src/features/ui-experience/`。
- 图片、图标和来源记录：`src/assets/ui-experience/`。
- UI保留多种示例场景；独立航班搜索、探索、收藏和提醒仍为前端样例/内存状态。真实规划入口与结果恢复按下述新增后端运行。
- `backend/src/` 是本轮新增的薄 Node HTTP API、DSH SDK 驱动、顺序协调器和展示适配；业务校验已按用户要求取消，没有恢复旧 Planner/DSH D6 服务。
- 航班 CLI 地点目录现离线包含 7,884 个 IATA 机场，覆盖 233 个国家/地区，上游 41 个多机场城市组并保留既有聚合。支持机场/城市代码、ICAO、英文名称和常用中文别名。已修复恢复历史日期后只向后翻月的故障：按可见年月双向导航。2026-10-19 正式 CLI 查询 BJS→PRG / 2026-10-28 / CNY 一次成功，25条结果中完整提取1项2150元报价和详情，39/39回归通过；目录覆盖不等同于全球航线报价保证，见 [AIRPORT_LOCATIONS](AIRPORT_LOCATIONS.md)。
- 规划页通过真实 API 提交需求，两个独立 DSH 0.2.1-rc.2 子进程分别规划/审核整理，各自有独立会话与工作目录。原始工具结果随草稿给审核者，结果直接展示，不做业务校验、审核否决或自动返工；资料不足也输出。
- 结果以 JSON 保存到忽略的 `backend/data/runs/`；H5/微信保存最近成功runId及当前对话ID，刷新通过只读GET恢复。对话中的行程展示快照还保存到对应助手消息，查看入口随消息恢复；旧记录从该对话自身已保存run补齐。真实结果的行程列表、收藏和机票文案不再标成固定样例。收藏、提醒、局部调整仍是内存行为，不会反写已保存结果。

## 边界

没有旧 API、数据库、Worker、云函数、管理后台或复制进仓库的 Provider 凭证。新后端复用用户 DSH 已有账户，当前模型路由 deepseek-account / deepseek-flash，未额外覆盖思考强度与输出上限。真实规划已验证，DSH通过现有CLI的航班查询已返回真实候选；独立航班搜索页仍是样例，未做自动监控。仅显式未传入后端生成器的组件预览保留原1.1秒样例延时；两个正式入口默认传入真实生成器，失败不降级成样例。

H5通过Vite把/api转发到127.0.0.1:3000；小程序使用Taro.request。地图仍用OpenStreetMap/微信组件，真实生成的坐标无依据则留空，不借用样例坐标或图片。新后端当前是单机、单并发、无业务认证的验证环境，尚不支持公网、多用户、持久任务恢复、真实改行程或预订。
