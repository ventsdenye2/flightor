# 微信模拟器海外地图灰底调查

日期：2026-10-25。适用于 `backend-mvp` 的微信每日地图。适配代码已提交为 `c764a1d`，本次调查不更换地图服务、不新增 Key 或位置权限。

## 结论

当前开发者工具默认地图通道没有显示所测海外城市的详细道路/POI底图。不是地图容器消失、景点缺坐标或所有地图请求都失败：同一个AppID、同一个Map组件，仅修改显示参数，北京和上海道路/POI正常，里斯本、巴黎和东京的城市级视图灰底；里斯本缩小到5级后有伊比利亚半岛海岸线。

这是对本机当前模拟器通道的实测结论，不能扩展为“腾讯地图全部产品不支持海外”或“所有手机必定灰底”。由于工具网络缓冲未暴露底图瓦片响应，本轮还不能进一步区分服务端缺少详细数据与海外数据通道的授权/配置限制。未得到海外瓦片HTTP状态或服务端明确错误，不以猜测代替证据。

## 排除与尚未证明的原因

- **不是缺坐标/错误城市**：原始节点、MapContext读取和海岸轮廓均对应里斯本；不是把纬经写反或误指向海上。
- **不是容器高度为0、遮罩覆盖或全局渲染失败**：原地图和国内对照共用同一个容器，国内底图、海外marker/折线均可见。
- **不是全部地图域名被拦截/整个SDK无法初始化**：国内道路和海外海岸轮廓真实显示。仍不能由此排除某个海外专用请求通道的问题。
- **不是普通的WGS84/GCJ02偏移解释**：坐标系偏移不能解释整个城市底图无道路，而改中心后国内详图正常。本次没有为此改写景点坐标；国内坐标系适配仍需独立处理。
- **不能简单归结为缺少subkey**：当前没有设置subkey，国内底图正常；腾讯组件文档将subkey列为非必填的个性化地图参数。新建Key或填写任意subkey不是已验证的修复方法，海外通道单独授权仍未核验。
- **额外位置接口权限错误与原灰底分开**：最初用于切换地图中心的诊断调用moveToLocation返回 `no permission`，并出现需要声明scope.userLocation的提示；该次对照无效。通过刷新恢复后，后续对照不调用用户定位接口，仍可得到国内正常/海外灰底结果。没有为浏览景点地图申请用户定位或更改权限。
- **工具日志边界**：get_simulator_network的全量grep结果为空，不能把它解释为地图完全没有发请求；原始灰底没有可用的瓦片HTTP响应证据。诊断脚本中不适用的API/数据路径实验已通过刷新恢复，不作为产品问题或有效对照。

## 后续路径

1. 在用户授权的iOS与Android真机分别检查同一里斯本行程；微信工具模拟器不能代替真机供应通道验收。本轮未上传、未预览到手机。
2. 若真机也缺少海外详细底图，应先确认所选地图产品/数据通道是否覆盖目标国家，再决定接入方案与Key/域名配置。H5当前使用的是Leaflet/OpenStreetMap，H5能显示不代表微信原生Map同样覆盖。
3. 继续保留有效景点编号、活动列表与详情；未实现自动识别“SDK正常但底图缺数据”的可靠状态检测，不把updated或无error事件当成底图加载成功。

未购入服务、未调用付费模型/航班供应商、未新增第三方地图API调用、未切换供应商。当前海外详细底图仍未修复，定位到的显示通道问题和未核验的服务端原因分别保留。
