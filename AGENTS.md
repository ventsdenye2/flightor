# Repository instructions

Read `docs/README.md`, `docs/PROJECT_CONTEXT.md` and `docs/DOCS_MAINTENANCE.md` before changes. This branch is the frontend baseline for a new backend MVP; its scope is documented in `docs/BACKEND_MVP.md`.

Keep the important documents under `docs/` continuously current. Every modification must include a corresponding update under `docs/` in the same change batch. Update the document that owns the behavior, contract or verification result, and record completed checks or changed boundaries there before finishing. Treat documentation as part of the implementation deliverable, not deferred cleanup.

Preserve unrelated changes and other worktrees. Use the user's current model settings; default to one agent unless delegation is explicitly requested.

Old backend planning, ADRs and handoffs remain in other branches/history. They do not define the new backend implementation or authorize calls to paid providers.
