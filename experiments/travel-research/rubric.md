# 活动候选研究：16 例人工盲评规则

本轮比较直接联网 LLM、现有 SerpApi + ProductionResearchAgent、轻量联网服务在**活动候选研究**上的表现。输入与现有 ResearchBrief 对齐，最多返回 6 个候选。首轮不计 UI，不验证完整 Planner E2E，也不把研究文本等同于持久化行程、旅行指南、已完成 Goal 或可购买产品。真实航班报价、预订、签证资格保证均不在范围内。

## 固定输入与运行条件

- `cases.json` 恰好 16 例，每例保留原始中文 `request`、结构化 `brief` 和人工验收参考 `expected`。每个 brief 的问题数量不超过 2。
- `destinations` 遵守 `backend/src/aviation/types.ts` 的严格 LocationRef 格式，使用 `type: "city"`，不是 `kind`。城市名称、ID、国家或地区代码是测试输入 fixture；没有宣称它们经过地点 Provider、航班 Provider 或业务授权验证。城市 ID 只承担用例身份，不证明其可直接用于生产地点解析。
- `travelWindow` 的总窗口不能替代问题中的细分日期、夜间时段、候选城市语义或冲突条件。活动 12 的两城日期、活动 13 的城市二选一、活动 14 的日期冲突都必须完整传入。
- 三条路线收到相同的研究意图与约束。直接消费 brief 的路线必须同时保留 `request` 中的任务语义；如果只支持 brief，先检查这些语义已进入 interests/questions，不能在某条路线丢掉硬约束。`expected` 和本评审规则不得进入模型输入。
- 先冻结用例、模型 ID/版本、推理档位、联网方式、超时、重试次数和费用上限，再运行。报告真实调用日期和可获得的版本信息；未来旅行日期不代表未来天气、开放、票价或节庆安排已经确定。用例日期过期后应统一更新全部路线的输入版本，不能只改一条路线。
- 同一轮尽量在相近时间交错运行各路线，记录联网地域/语言、缓存和失败状态。至少做 1 次完整探索轮；正式比较建议每例每路线重复 3 次，并保留全部尝试，不能挑选最好一次。
- 调用授权与预算由运行者在实际联网运行前确定。本文件及 fixture 校验不需要联网、读取密钥或产生调用费用。

## 匿名与统一呈现

保存原始响应及原始来源，在独立副本中隐藏供应商、模型、路线名及可识别的系统文案，随机分配评审编号。只改变呈现方式，不修正模型事实。给评审者展示统一的文字候选列表、条件、来源链接和不确定性，不用卡片、颜色、地图或排版质量影响评分。来源本身可能暴露路线，记录这种匿名局限。

两名评审独立评分后再复核差异。评审可见同一份用户请求、brief、人工检查点和原始证据；复核来源所花时间计入评审工作量，不计入用户侧生成延迟。每个扣分必须指向具体候选或陈述。无法核实写“待核实”，不能凭印象判真或用另一模型当事实裁判。

若某条路线需要额外 LLM 将输出转换为统一格式，应保留转换前后内容，核查是否新增事实、丢失限定或删除失败项。该转换是路线的一部分，其额外调用、token、费用和延迟全部计入。机械字段映射也记录耗时，但不得悄悄使用隐藏的补写模型修复结果。

## 100 分人工评分

100 分是人工尺度，不是从链接数、schema 合法率或关键词匹配计算的自动总分。每个维度给整数分并附证据；无法评分时填 N/A 并说明原因，不得用 0 或平均值冒充已评。分数用于在同一用例与标准下比较，不代表旅行事实正确率。

| 维度 | 分值 | 满分依据 | 主要扣分依据 |
| --- | ---: | --- | --- |
| 意图与约束理解 | 25 | 城市、日期、人员、预算、硬约束与用户允许的范围全部保留；识别必须澄清的冲突 | 丢失硬约束、误读预算、跨城/日期串位、擅自改计划或缺少关键澄清 |
| 事实证据与来源支撑 | 30 | 关键事实可逐条追溯到相关内容，日期与适用范围正确，来源权威程度与主张相称 | 引文不支持主张、拿往年当当年、来源只覆盖部分却作完整保证、虚构事实或来源 |
| 候选适配与实用性 | 20 | 候选符合兴趣及可行条件，有足够差异，位置/时长/限制能支持下一步选择；必要时少给 | 堆砌同义景点、偏离任务、用无关候选凑 6 条、遗漏影响选择的重要信息 |
| 时效与不确定性处理 | 15 | 区分已公布、经验估计、未知及需要确认事项，正确处理未来活动、自然条件和信息不足 | 把未知写成确定、虚假保证、仅有泛泛免责声明却掩盖具体缺口 |
| 范围与下一步表达 | 10 | 简洁明确；推荐、澄清或部分结果状态与证据一致；下一步可执行，最多问 2 个问题 | 擅自声称已保存/预订/完成 Goal、输出与任务不相干的整套规划、过度追问或掩盖失败 |
| **合计** | **100** | **人工逐项评分并附依据** | **不由客观诊断字段自动生成** |

建议使用每维满分、约四分之三、约一半、约四分之一、零分这五档作为初始锚点，再用具体证据给整数分。对应语义为：完整满足；轻微缺口；影响选择的重要缺口；大部分不可用；没有可用贡献或结论与输入直接冲突。不要给小数分制造精度。

`expected.disposition` 是用例设计时的主要响应方式，不是机械字符串断言。`recommend` 允许可靠资料不足时诚实降为部分结果；`partial` 允许日后官方资料充分时升级为推荐，但必须记录支持升级的证据。`clarify` 用例不能通过编造缺失信息获得满分。缺少标准化 disposition 字段时，由评审根据真实内容标注。纯澄清用例按“是否必要且足够解决当前阻碍、有没有编造候选”评判实用性；不能因为没输出 6 个候选而扣分。事实证据维度评判其已有事实主张及对无证据推断的克制，不要求给简单日期冲突添加无意义引用。

逐例检查 `expected.checks` 和 `expected.forbiddenClaims`，分别写“满足 / 部分 / 未满足 / 无法核实”及依据。禁止声称清单用于提醒具体失误，不能靠字符串命中自动判错，也不应成为模型提示补丁。

## 独立客观诊断：不进入人工总分公式

| 诊断 | 定义及报告方式 | 不能推出的结论 |
| --- | --- | --- |
| 原始结构合法 | 按该路线声明的原始合同验证，记录 pass/fail 和错误路径；未承诺结构格式的路线记 N/A | 结构合法不代表内容真实或业务任务完成 |
| 归一化结构合法 | 所有路线按同一规范验证归一化结果，记录 pass/fail、修复方式及字段损失 | 修复成功不能抹掉原始失败或额外调用 |
| 候选数量与重复 | 报告候选数、超上限、按地点/体验人工识别的重复数；澄清响应可为 0 | 更多候选不自动更好，少于 6 项不自动失败 |
| citation-linked | 候选含至少一个可解析、可关联来源 URL 的数量 / 实际候选数；零候选记 N/A | **链接存在不等于事实真实；链接相关也不等于支持所有事实** |
| 主张与引文关联 | 若系统输出可识别的事实主张—引文映射，报告关键主张中有映射的数量 / 关键主张数；无映射则记未提供 | 模型自报的映射、verified、confidence 不能替代阅读证据 |
| 链接访问状态 | 在评审时记录可访问、重定向、失效或受限；同时记录检查时间 | 403/登录墙不自动代表虚假，HTTP 200 不证明正文支持主张 |
| 日期与城市诊断 | 机械报告显式日期重叠、已标注城市、明显字段冲突，另由人工解释 | 缺少显式日期不自动表示活动不可用；总窗口重叠不保证城市分段适配 |
| 执行与交付状态 | 报告成功、超时、Provider 错误、费用上限触发、空结果和部分结果；保留错误原文的脱敏副本 | HTTP 成功、模型结束或 schema 通过不等于已得到可用候选 |

Source URL 检测只检查存在和可关联性，不能使用随意的“可信来源域名白名单 + 链接数”计算事实质量。搜索结果片段与网页正文应分开标记；评审需阅读支持主张的实际内容，核对年份、适用人群、时段及否定或附带条件。若网页不可访问且只有片段，明确保留该证据限制。

## 延迟与成本分开报告

每次尝试至少记录：路线、用例、重复编号、开始/结束时间、总墙钟耗时、是否命中缓存、超时与重试、联网查询次数、模型调用次数、归一化/纠错调用次数、输入/输出 token、已知费用及费用来源。并行调用记录各自耗时和端到端墙钟，不把各子调用耗时简单相加冒充用户等待时间。

端到端延迟从路线接收完整测试输入开始，到可供统一评审的最终结果返回为止，包含搜索、抓取、重试、归一化和必要纠错；另列首次响应时间或原始生成时间（若可测），不可拿流式首 token 与另一条路线的最终完成时间比较。按路线给出成功/失败数量、样本数、中位数和分位数，并保留逐例原始值；样本少时提醒分位数不稳定。

成本必须包含搜索服务、模型推理、额外联网及归一化调用。供应商账单或响应 usage 优先；只有估价时附价格版本、计费单位和估算公式。未知费用写 unknown，不按免费算。订阅包、配额、缓存折扣及失败请求收费独立注明。报告每次尝试成本、每例含重试总成本、路线总成本和产出可用结果的成本；“可用”定义由事先固定的人工阈值与严重错误门槛决定，禁止在看到结果后挑阈值。没有实际联网运行时只报告“未测”，不预填速度、费用或模型排名。

## 结果表与结论边界

建议逐例人工记录：匿名编号、用例 ID、实际 disposition、五维整数分、人工合计、关键检查结果、严重错误、证据链接与摘录位置、缺口、是否需复核。单独保存客观诊断表与延迟/成本表，揭盲后再做路线映射。不要让供应商名称影响评分。

严重错误单独列示，包括虚构来源、虚构时效活动、未核实的过敏安全或入境保证、忽略硬约束却声称满足、声称已保存/预订/完成业务。严重错误不靠其他维度平均分掩盖；总体结论必须同时展示其数量、涉及用例与证据。

路线比较优先看同用例配对结果、关键人群和约束覆盖、重复间波动、人工分歧及严重错误，再看质量—延迟—费用取舍。16 例是代表性小样本，不能宣称覆盖所有旅行需求。报告可推荐的实验路线及适用范围，区分实测、静态检查、未验证项目；任何“可以替代完整 Planner”“生产已验收”“真实 Provider E2E 已通过”的结论都需要本轮之外的独立证据。
